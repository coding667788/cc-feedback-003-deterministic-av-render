请从零开发一个面向离线成片生产的音视频时间线渲染引擎。输入素材可能具有不同帧率、可变帧间隔、不同音频采样率及非零起始时间戳。用户提供剪辑时间线后，系统必须输出时间关系正确的成片，并在分段渲染、缓存复用或中断恢复后保持同一解码结果。不能只拼出一条在某个固定样例上碰巧可用的 FFmpeg 命令。

使用 Windows 原生 Python 3.12，允许调用本地 FFmpeg/ffprobe 完成编解码和基础滤镜处理；项目解析、时间映射、分段计划、缓存与恢复、验证逻辑必须自行实现。使用 CPU 软件编解码并记录确切版本，不依赖 Docker、GPU 编码、云端素材或付费服务。当前没有已有业务代码；素材生成器、项目样例、渲染器和验证器均属于本次交付，无需等待外部附件。

一、项目模型与时间规则
1. 定义并实现 JSON 工程格式。所有时间、速度和时间基都以整数分子/正整数分母表示，禁止用逐段累加浮点秒作为权威时间轴。片段至少包含素材标识、源区间 [in,out)、时间线起点和正有理数速度；还要支持空隙、同轨相邻片段的重叠转场，以及独立的背景音轨。
2. 必须支持常帧率与可变帧率视频；选帧以解码后的显示时间戳为准，不能把帧序号除以一个平均 fps 代替时间映射，也不能假定解码顺序等于显示顺序。素材允许有 B 帧、音视频不同起点以及合法的非零起始 PTS。缺失或自相矛盾的关键时间信息须显式拒绝，不能猜测后宣称精确。
3. 输出默认 30000/1001 fps、48 kHz 双声道。时间线计划时长为 D，输出视频帧数 N=ceil(D×30000/1001)，规范化输出时长 Dq=N×1001/30000。第 n 帧在时间线时刻 (n+1/2)×1001/30000 采样；映射到源后，选择显示 PTS 不大于该时刻的最近一帧。源区间和时间线区间均为左闭右开，区间外及时间线空隙输出黑场；最后不足一帧的填充区也按这一规则处理。
4. 音频输出样本数为 round_half_up(Dq×48000)，第 k 个样本以 (k+1/2)/48000 为采样时刻。片段边界、淡入淡出及转场权重必须从同一全局时间坐标求得，不能对每段独立取整后再拼接。允许变速同时改变音高，不要求变速保调；重采样可使用 FFmpeg，但必须控制并验证样本边界。
5. 支持可选的双锚点时钟校准：工程中给出两个单调的“音频源样本位置—视频源时间”对应点，二者唯一确定仿射映射。校准后裁切、变速与转场必须继续使用同一映射；不得从内容中猜测未提供的时钟偏差。零长度区间、非正速度、逆序锚点、无法支持的重叠关系要在开始渲染前报告。

二、合成与颜色/音量语义
6. 支持硬切和线性叠化。一个视频轨同一时刻最多两个片段活动，重叠区两者权重和为 1；输入工程出现三重重叠时应拒绝。背景音轨可与主音轨叠加，音量包络在全局样本时刻求值，并明确溢出限幅规则。不能因为转场而重复或丢掉边界帧、边界样本。
7. 本题仅要求 SDR Rec.709、已声明像素格式/色彩范围的素材；不要求 HDR。固定工作像素格式、尺寸缩放、黑边策略、重采样与舍入方式，并写入工程结果元数据。所有输入先进入一致的工作格式，不能让不同渲染路径采用不同隐式默认值。

三、分段、缓存和恢复必须保持语义
8. 实现由规范化时间线生成的渲染依赖图和有界并行调度。分段位置可以落在 GOP 内、变速片段内或转场中间；必须为解码依赖、重采样滤镜历史和转场获取必要前后文，再按全局整数帧/样本编号裁出本段负责的区间。相邻段不能各自重复负责同一个边界。
9. 缓存键必须覆盖输入文件内容摘要、源区间、时间映射、影响本段的邻接转场/包络、工作格式和 FFmpeg 版本等实际依赖。同名素材被替换、只改一处转场长度、只改音频校准锚点，都不能误用旧缓存；与改动无关的片段应继续复用，并提供可核查的命中记录。
10. 半成品、完整中间片段、已经发布的成片必须区分。渲染期间取消任务或强制结束进程后，重启不能把不完整片段当缓存，也不能破坏上一份已发布成片。仅在所有片段与全局时长验证通过后发布新版本；失败要保留明确诊断及可恢复状态。
11. 提供 lossless 验证产物：固定格式的无损视频中间结果和浮点或无损 PCM 音频。整段渲染与任意合法分段后恢复的结果应有相同视频帧数、顺序、时间戳及工作格式像素；音频样本数、时间位置一致，样本数值误差不超过预先声明的严格容差，例如归一化浮点绝对误差 1e-6。不得把逐段重置滤镜造成的差异藏在很宽松的容差里。最终另输出可播放 MP4；压缩文件本身不要求字节完全一致，AAC 延迟/填充必须说明并在验证中正确处理，不能拿编码器填充掩盖时间线漂移。

四、必须实际验证的组合场景
实现确定性素材生成器：视频用机器可解码的颜色/二进制图案标识源帧，音频用已知位置的脉冲及连续波形作定位，不依赖外部字体或人工听感。生成 25 fps、30000/1001 fps、可变 PTS 间隔视频，以及 44.1/48 kHz 音频；包含非零起点、无音轨素材和带 B 帧编码的素材。

至少验证：非关键帧入点；1/3 秒等非整数帧边界；3/2 与 2/3 倍速；转场跨渲染段；音频与视频起点不同；带锚点校准的长时间线；空隙和静音；同名输入内容变化；只改邻接转场的缓存失效；片段已写完但完成标记尚未提交时中断；已完成部分分段后恢复；非法工程不产生伪成功成片。

用至少三种不同分段大小、两种并行度对同一工程进行整段/分段/恢复对照。长时间轴验证可采用低分辨率合成素材，但必须覆盖至少 30 分钟的累计时间，证明不会逐段积累一帧或一个采样点的错位。验证器应从输出中独立解码帧标记和音频定位标记，与工程规范计算出的期望位置对照，不能只信任渲染器自己打印的成功日志。

交付工程格式说明、核心库、批量渲染入口、素材生成器、自动化验证器、测试及 Windows 操作说明。展示实际命令、输出元数据、误差统计、缓存失效范围和中断恢复步骤。重点说明有理时间、选帧、采样、滤镜前后文和片段拼接如何形成同一个可验证的时间系统；未完成或未验证的部分请明确列出。
